# 保研追踪表结构

建议至少包含 7 张表：`用户画像`、`院校库`、`院校画像`、`项目节点`、`我的申请`、`更新日志`、`提醒队列`。

面向小白用户时，默认生成 Excel 工作簿，并给每张表开启筛选、冻结首行、设置列宽。用户不需要手动建表；agent 应先创建模板，再把检索到的官方信息填入对应工作表。

## 用户画像

用于冲稳保分档。没有用户画像时，不得强行推荐冲稳保。

| 字段 | 说明 |
| --- | --- |
| user_id | 稳定 ID |
| 简历/材料来源 | 上传文件/粘贴文本/手填/未提供 |
| 简历解析状态 | 已解析/部分解析/待补充/未提供 |
| 目标年份 | 如 2027 届、2026 年夏令营 |
| 目标专业/方向 | 用户明确提供的专业；不要默认新闻传播或任何特定专业 |
| 本科院校层次 | 985/211/双一流/双非/中外合作/其他 |
| 本科专业 | 用户本科专业 |
| 排名/绩点 | 年级排名、专业排名或 GPA |
| 英语水平 | 四六级、雅思、托福等 |
| 科研/竞赛 | 项目、竞赛、论文、课题等 |
| 实习/论文/作品 | 实习、论文、作品集、项目经历等 |
| 地区偏好 | 城市/地区 |
| 学硕/专硕偏好 | 学硕/专硕/均可 |
| 风险偏好 | 激进/均衡/稳妥 |
| 备注 | 其他重要约束 |

用户上传简历/个人材料时，先填 `用户画像`，再基于用户画像做冲稳保。不要在最终输出中暴露手机号、邮箱、身份证号、住址等敏感信息。

## 院校库

用于筛选择校。

| 字段 | 说明 |
| --- | --- |
| school_id | 稳定 ID，如 `fudan-sjc` |
| 学校 | 高校名称 |
| 学院/学部 | 具体招生单位 |
| 城市 | 可筛选 |
| 地区 | 华北/华东/华南/华中/西南/西北/东北/港澳台等 |
| 学校层次 | 985/211/双一流/双非/中外合作等 |
| 学科/专业 | 用户目标学科/专业 |
| 信息年份 | 公告或资讯对应年份，如 2026；未知写待核验 |
| 是否往届信息 | 是/否/待核验；与用户目标年份不一致时填是 |
| 学科排名 | 用户指定口径；记录来源 |
| 专业类型 | 学硕/专硕/均有/未知 |
| 学费 | 金额、单位、年份；未知则留空 |
| 学制 | 年数 |
| 是否有夏令营 | 有/无/未确认/历史有 |
| 夏令营时间 | 报名、入营、考核、结果等关键日期；未知写待核验 |
| 是否有预推免 | 有/无/未确认/历史有 |
| 预推免时间 | 报名、复试/面试、结果等关键日期；未知写待核验 |
| 是否通常九推 | 有/无/不稳定/未知 |
| 九推时间 | 全国推免系统填报、复试、待录取确认等关键日期；未知写待核验 |
| 学校官网 | 学校主站 URL |
| 研究生院/研招网 | 研究生院或研究生招生网 URL |
| 学院官网 | 学院/学部/系官网 URL |
| 招生专题/报名系统 | 招生专题页、夏令营/推免报名系统 URL |
| 官方公众号 | 名称或链接 |
| 备注 | 只放无法结构化的重要信息 |
| 信息状态 | 已官方核验/待核验/历史参考/冲突 |
| 最后核验日期 | YYYY-MM-DD |

## 院校画像

用于全面推荐。每所学校至少一行；不要只用单一指标推荐。

| 字段 | 说明 |
| --- | --- |
| profile_id | 稳定 ID |
| school_id | 关联院校库 |
| 学校 | 高校名称 |
| 学院/项目 | 招生单位或项目 |
| 信息年份 | 画像依据的主要资讯年份 |
| 是否往届信息 | 是/否/待核验 |
| 学校官网 | 学校主站 URL |
| 研究生院/研招网 | 研究生院或研究生招生网 URL |
| 学院官网 | 学院/项目官网 URL |
| 专业方向匹配 | 高/中/低/待核验 |
| 学术/学科优势 | 学科实力、研究方向、平台；写来源 |
| 导师/研究方向 | 与用户方向相关的导师、团队、实验室或课程 |
| 专硕培养特点 | 实务导向、实习、作品、行业合作等；无则写未知 |
| 学硕培养特点 | 学术训练、论文、研究方向等；无则写未知 |
| 城市与行业资源 | 城市、媒体/互联网/广告/政务/文化产业资源 |
| 就业与实习线索 | 官方就业质量报告、学院新闻、校友去向等 |
| 学费与生活成本 | 学费、住宿、城市成本；未知则待核验 |
| 住宿/奖助信息 | 宿舍、奖学金、助学金；未知则待核验 |
| 申请难度 | 高/中/低/待评估；说明依据 |
| 考核偏好 | 论文/英语/作品/实习/专业面/综合面/笔试等 |
| 夏令营价值 | 强/中/弱/无/待核验；结合效力和入营收益 |
| 预推免价值 | 强/中/弱/无/待核验 |
| 九推机会 | 高/中/低/不稳定/未知 |
| 主要优势 | 2-3 条，必须来自表格或官方来源 |
| 主要风险 | 2-3 条，如截止早、效力弱、竞争强、费用高、信息少 |
| 适合人群 | 如科研强、实习强、英语强、想留某城市等 |
| 不适合情形 | 如预算敏感、只想线下、只要铁 offer 等 |
| 推荐档位 | 冲/稳/保；必须基于用户画像 |
| 分档依据 | 说明为什么相对于该用户是冲、稳或保 |
| 推荐理由摘要 | 依据 -> 判断 -> 动作，一句话 |
| 画像来源 URL | 官方或可信来源 URL；多个来源用分号分隔 |
| 信息状态 | 已官方核验/待核验/历史参考/冲突 |
| 最后核验日期 | YYYY-MM-DD |

## 项目节点

一行代表某校某年某环节。

| 字段 | 说明 |
| --- | --- |
| program_id | 稳定 ID，如 `2026-fudan-sjc-summer` |
| school_id | 关联院校库 |
| 年份 | 如 2026 |
| 是否往届信息 | 是/否；与用户目标年份不一致时填是 |
| 环节 | 夏令营/预推免/九推/补录/其他 |
| 项目名称 | 公告标题中的名称 |
| 报名开始 | YYYY-MM-DD |
| 报名截止 | YYYY-MM-DD HH:MM；未知留空 |
| 报名入口 | URL |
| 材料要求 | 简历、成绩单、排名证明、英语、论文、作品等 |
| 考核形式 | 线上/线下/混合/未公布 |
| 地点 | 城市、校区、楼宇；线上写平台 |
| 入营/入围通知日期 | YYYY-MM-DD |
| 考核日期 | 日期范围 |
| 结果发布日期 | YYYY-MM-DD |
| 夏令营效力 | 强效力/弱效力/无效力/未披露/不适用 |
| 效力依据 | 公告摘要；不要只写判断 |
| offer 类型 | 优秀营员/候补/拟录取/待录取/无 |
| 专硕/学硕 | 学硕/专硕/均有/未知 |
| 招生名额 | 数字或公告表述 |
| 学校官网 | 学校主站 URL |
| 研究生院/研招网 | 研究生院或研究生招生网 URL |
| 学院官网 | 学院/项目官网 URL |

| 抓取日期 | YYYY-MM-DD |
| 信息状态 | 新增/已核验/有变更/已截止/历史参考/冲突 |

## 推荐筛选项

- 城市、地区、学校层次、学科排名、专业类型、学费、学制。
- 信息年份、是否往届信息、是否有夏令营、夏令营时间、是否有预推免、预推免时间、九推时间、夏令营效力、线上/线下。
- 报名状态、初审状态、是否入营、offer 状态、面试状态。
- 截止日期、优先级、匹配度。
- 专业方向匹配、申请难度、考核偏好、夏令营价值、预推免价值、九推机会、推荐档位。

## 覆盖性检查清单

完成表格前逐项自查：

- 是否能看出哪些学校有夏令营、哪些只有预推免、哪些通常走九推。
- 如果搜索到的是往届时间或资讯，是否明确标为“往届信息/历史参考”，并提醒用户不能当作目标年份结论。
- 是否能看出每个学校的夏令营时间、预推免时间、九推时间；未知时是否标为待核验。
- 是否能看出夏令营是否有录取效力，以及效力依据来自哪条公告。
- 是否记录了报名入口、报名截止、材料要求、考核形式、地点。
- 是否记录了专硕/学硕、学费、学制、招生名额。
- 是否建立了院校画像，覆盖学术优势、方向匹配、城市资源、就业线索、成本、申请难度、考核偏好、优势和风险。
- 是否建立了用户画像，并根据用户背景输出三档 `冲`、`稳`、`保`；例如本科 211 用户申请 985 项目通常先按冲评估，不能默认标稳。
- 是否能筛选城市、地区、学校层次、学科排名、专业类型。
- 是否能记录用户自己的报名、入营、参营、优秀营员、offer、面试、九推确认状态。
- 是否有学校官网、研究生院/研招网、学院官网、具体公告 URL、发布日期、抓取日期和信息状态。
- 是否有下一步待办和截止提醒。
- 是否主动询问用户是否需要设置每日/每周定时任务。
- 推荐是否至少引用 3 个维度，而不是只看排名、城市、费用或 offer 效力。
- 推荐档位是否只有冲、稳、保三档，并写清分档依据。
